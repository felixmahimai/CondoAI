5 · User journey flow of the prototype

The prototype compresses the scope's master spine (workspace → knowledge → cited answer → approval → action → task → audit → memory) into an interactive loop. Numbers on the diagram match the step tables below.

A · A1 manager happy path (Maya → Mapleview)

  1. Sign in as Maya Miller (A1 manager) → password → MFA step → workspace loads.
  2. Dashboard (4): greeting, KPIs (4 open tasks · 2 approvals · 2 incidents · 1 warranty alert), "Needs your attention" (escalated noise task, AGM notice, roof warranty), recent activity.
  3. Assistant (5): ask "What are the pet rules?" → cited answer (Declaration §7.2). Ask an off-corpus question → marked Unverified / Not Available with follow-ups.
  4. Workflows (5) → Q17 gate (6): Comms branch → AI draft of AGM notice → Submit for approval (drafting authorizes nothing).
  5. Approvals: approve the notice with an outcome note (Maya's role is in the comms matrix) → spend item stays blocked (C1/Board only).
  6. Action + task (7) → Audit + Memory (8): approval recorded with approver + timestamp; completion feeds Institutional Memory as a new version. Check record integrity in the Audit Trail.

B · Denial path (Sasha → Mapleview)

  1. Sign in as Sasha Lee (active A1 plan, Oakridge grant only).
  2. Attempt any Mapleview retrieval → neutral message, zero data, returned to own dashboard; attempt logged with identity/timestamp/resource/reason.

C · Role-specific paths
